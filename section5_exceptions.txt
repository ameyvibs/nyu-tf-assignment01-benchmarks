Section 5: Bad decision #2 (exceptions for risk checks)
=======================================================
Supports: (a) a failed check that throws costs ~3,300 ns vs ~0.7 ns returning false;
(b) average tick-to-trade about 3-5x lower on position and loss after the fix
(position: 463 ns -> 134 ns), roughly unchanged on basic (limit never hit).

(a) Microbenchmark (single-file C++ program, -O2, Apple M4), 3 runs:
┌────────────────────────────────────────────┬───────┬───────┬───────┐
│ case (ns per check)                        │ run 1 │ run 2 │ run 3 │
├────────────────────────────────────────────┼───────┼───────┼───────┤
│ first throw ever (one-time)                │ 39625 │ 25791 │ 23500 │
├────────────────────────────────────────────┼───────┼───────┼───────┤
│ failed check, throw (avg of 100k)          │  3235 │  3310 │  3269 │
├────────────────────────────────────────────┼───────┼───────┼───────┤
│ failed check, return false (avg of 100k)   │   0.7 │   0.7 │   0.7 │
├────────────────────────────────────────────┼───────┼───────┼───────┤
│ passed check, nothing thrown (avg of 100k) │   1.3 │   1.3 │   1.4 │
└────────────────────────────────────────────┴───────┴───────┴───────┘

(b) Full app, tick-to-trade. Before = risk checks throw; fix = checks return a
[[nodiscard]] bool. Each fixture run 300 times per version, timings pooled,
run back to back: before -> fix -> before.
Fixtures gap, quiet, empty_side send only 1-3 orders per run: mostly noise.
n = messages counted per run. All times in ns.
