Section 3: Good decision (flat array for order lookup vs std::unordered_map)
============================================================================
Supports: average per-message handling time (handler-all) 30 ns with the array vs
63 ns with std::unordered_map.

Scenario: synthetic "big" scenario (200k resting orders, 100k churn events,
~300k messages), generated with seed 1. Each version run 30 times, timings pooled.
Run back to back: array -> hash map -> array, so noise is visible (both array runs match).
The supplied fixtures hold only a few dozen orders and show no difference.
n = messages counted per run. All times in ns.
