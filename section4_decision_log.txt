Section 4: Bad decision #1 (fprintf decision log before every send)
===================================================================
Supports: tick-to-trade p50 dropped about 3-5x on the supplied fixtures
(basic: 292 ns -> 83 ns).

Baseline = original trading code (+ evaluation fix). Fix = 32-byte record stored into a
shared mmap before each send; text log written after the sends.
Each fixture run 300 times per version, timings pooled, run back to back.
(The "commit" line inside both outputs shows the same label because the code under test
was swapped in for each run; the section headers below say which version ran.)
Fixtures gap, quiet, empty_side send only 1-3 orders per run: mostly noise.
n = messages counted per run. All times in ns.
